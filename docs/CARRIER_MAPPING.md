# Carrier mapping and verification

## Canada Post

Verified against the official [Get Rates REST documentation](https://www.canadapost-postescanada.ca/info/mc/business/productsservices/developers/services/rating/getrates/default.jsf), [Discover Services](https://www.canadapost-postescanada.ca/info/mc/business/productsservices/developers/services/rating/getrates/discoverservices.jsf), [Get Service](https://www.canadapost-postescanada.ca/info/mc/business/productsservices/developers/services/rating/getrates/getservices.jsf), and [Get Option](https://www.canadapost-postescanada.ca/info/mc/business/productsservices/developers/services/rating/getrates/getoption.jsf).

The adapter uses POST `/rs/ship/price`, Basic API key/secret authentication, the v4 rate media type and namespace, and fixed sandbox/production hosts. It submits Canadian origin postal codes, country-specific destinations, kg/cm parcel values, ship date, and explicit quote type. Commercial requests include configured customer/contract numbers; counter requests omit them. Sandbox is configured for counter (retail) prices after commercial requests returned AA004. Counter rating succeeded with the same API credentials; rates disclose that account discounts are not applied. Production defaults to commercial unless explicitly configured otherwise. Service filtering is omitted to request applicable services. `SO` requests signature and `COV` with `option-amount` requests coverage. The `due` response is the carrier total including taxes; delivery fields are taken directly from the carrier. Dimensions are sorted and rounded to one decimal, weight to three decimals at the boundary. Carrier validation determines option eligibility and limits; service-level option discovery is not yet cached or enforced locally.

## FedEx

Consulted the official [Rates and Transit Times guide](https://developer.fedex.com/api/en-us/catalog/rate/v1/docs.html), [Authorization guide](https://developer.fedex.com/api/en-us/catalog/authorization/docs.html), and [integration practices](https://developer.fedex.com/api/en-ch/guides/best-practices.html). Local `doc/fedex/service_availability_api/service-availability.json` confirms the distinct sandbox/production hosts but describes Availability, not Rates.

The adapter uses mode-specific client-credentials OAuth at `/oauth/token` and rate POST `/rate/v1/rates/quotes`. It omits service type to request multiple services, asks for transit information, requests account rates and prefers returned ACCOUNT details over LIST details to avoid duplicate service rows, passes declared value at the package level, and requests direct signature when selected. Own packaging and FedEx-location drop-off are explicit assumptions. Whole-centimetre dimensions are rounded up and disclosed. Response amounts use carrier totals; unknown currency is marked UNKNOWN, and inclusive-tax claims require the inclusive total field. Delivery dates are estimated, not invented commitments.

The public guide confirms capabilities but does not expose the complete interactive request schema without portal access. Exact field compatibility, signature eligibility, date behavior, Canadian taxes, and account enrollment need verification using the credentialed developer portal and sandbox. This implementation is not certified against a real FedEx account.

## Loomis: inspected local references

Sources: `LoomisExpressWebServices-LShipv1.10-Guide 2024.pdf` (especially pages 7, 56, 58, 60–63, 91), and the `II.RATE-Operation1` through `II.RATE-Operation5` request/response samples in `LoomisExpressWebServices-LShipv1.10-XML 2024`. The provided material is preserved locally and ignored for publication; no credential values are reproduced here.

The rating namespace is `http://ws.rating.uss.transforce.ca`; request DTO namespaces use its `/xsd` and `http://dto.uss.transforce.ca/xsd`. Documented active operations are `isResidential`, `getAvailableServices`, `getRates`, `getPublicRates`, and `getVersion`. `rateShipment` and `submitManifest` are inactive. This application must use rating only.

`getAvailableServices` requires `user_id`, `password`, `shipper_num`, origin/destination postal codes, Canadian destination country, and `shipping_date` in YYYYMMDD. `getRates` adds a shipment with pickup/delivery address, name, city, province, packages, and phone where required. `service_type=ALL` requests all services. Metric dimensions use `dimension_unit=M`, kilograms use `reported_weight_unit=K`, and package dimensions appear in `package_info_num` arrays with `LENGTH`, `WIDTH`, `HEIGHT`; weight is `reported_weight`.

Declared value uses `shipment_info_num` / `DECLARED_VALUE`. The guide limits ordinary declared value to 2499.99 CAD, with a special agreement required at 2500–5000. Signature uses `shipment_info_str` / `SIGNATURE` with `SR`, `SA`, or `NSR`. Omit residential classification to let Loomis determine it; do not assume false. All mandatory address/contact requirements must be validated before enabling the adapter.

The response contains `getRatesResult` / `shipment`, charges in named numeric arrays, tax charges/codes, `estimated_delivery_date`, `transit_time`, and `transit_time_guaranteed`. Page 63 confirms `TOTAL_CHARGE` already includes its displayed taxes; do not sum it again. `ADD_SER_CHARGE` aggregates add-on charges and must not be added to the individual `CHARGE_*` amounts. Appendix A maps DD to Ground, DE to Express 18:00, DN to Express 12:00, and D9 to Express 9:00.

The sandbox WSDL was retrieved and its SOAP 1.1 binding verified. Rating uses `https://sandbox.loomis-express.com/axis2/services/USSRatingService.USSRatingServiceHttpsSoap11Endpoint/` with SOAPAction `urn:getRates`. The adapter sends `shipping_date` as YYYYMMDD and parses `getRatesResponse.return.shipment`. A credentialed domestic sandbox request returned four services. The SOAP request requires street addresses, contact names (or company names), and phone numbers. Empty sandbox fields use the visible test defaults (1 Test Street, Sandbox Sender/Recipient, 6045550100) and disclose this in quote notices. Supplied values and saved profiles are preserved; these defaults are never used in production. International requests return an explicit unsupported error because customs information is not implemented. For production, enter the carrier-provided HTTPS SOAP 1.1 rating endpoint, username, password and account ID in Settings, save, then Test connection. Production requires complete real street/contact/phone details. Only official Loomis domains are accepted, and sandbox URLs are rejected in production; credentials are isolated by mode. No production endpoint is guessed or prefilled.

## Service visibility and sample quotes

Canada Post and FedEx request all eligible services; Loomis sandbox requests `service_type=ALL`. Eligibility depends on the route, package, and account. Only actual response amounts and delivery information are displayed. Failed requests show errors, with no synthetic fallback.

Automated-test fixtures cover 12 domestic sample services, plus separate U.S. and international samples. Service names follow [Canada Post's service list](https://developer-developpeur.canadapost-postescanada.ca/devportal-portaildesdeveloppeurs/ship-parcels), [Loomis domestic services](https://www.loomisexpress.com/loomship/Services/ShippingInCanada), [Loomis international services](https://www.loomis-express.com/loomship/Services/ShippingInternational), and the [FedEx Canada service guide](https://www.fedex.com/content/dam/fedex/ca-canada/MVP/downloads/CA_EN_2022_FedEx-Service-Guide.pdf). Prices, transit times, and eligibility in fixture mode are synthetic, rather than carrier commitments or exhaustive live availability.

Carrier selection in the web form determines which carriers receive rate requests. Carrier API URLs, credentials and enable switches are stored in encrypted per-account settings through the web UI. Account quotes never fall back to carrier environment variables. Users can hide individual returned services; choices are stored per account in the current browser. All rate variants for a hidden service are excluded from the display and clipboard export. Copy table writes both formatted HTML and bordered, aligned plain text, with only carrier, service, delivery, rate(s) and signature. It excludes quote details, environment/variant labels, declared-value notes and status blocks, while preserving all shown rows and the selected tax basis. Copy API result beside each row's status provides the original per-service response data (parsed service objects for XML carriers), including base and covered responses when returned. Hidden services remain excluded from the table export.
